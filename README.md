# دليل — المساعد التعليمي الإسلامي

نسخة محلية أولية لمساعد متعدد اللغات يجيب من الكتب والمناهج المعتمدة فقط.

## التشغيل المحلي

1. انسخ `.env.example` إلى `.env.local`.
2. ضع مفتاح OpenCode في `OPENCODE_API_KEY`، ثم شغّل `npm run audit:init` لتوليد مفتاح HMAC عشوائي مستقل (32 بايت) داخل `.env.local` من دون طباعته. يكتب الأمر ملفًا مؤقتًا متزامنًا ثم يستبدل الملف ذريًا ويزامن مجلد الملف حيث يدعم النظام ذلك، ويرفض استبدال مفتاح موجود. يستخدم كل تشغيل lock ticket فريدًا حتى لا يحذف تشغيلٌ قفل تشغيل آخر، ويستعيد تلقائيًا ticket أقدم من عشر دقائق؛ لا تحذف قفلًا أحدث يدويًا قبل التأكد من عدم وجود عملية `audit:init` عاملة. على Windows ستظهر تحذيرات ثابتة لأن صلاحيات POSIX لا تتحقق من ACL ولأن مزامنة metadata للمجلد غير متاحة؛ راجع خصائص أمان `.env.local` يدويًا واقصر القراءة على الحساب المقصود والمديرين الموثوقين. لا ترسل أيًا من المفتاحين إلى الشات أو تضعه في متغير يبدأ بـ`VITE_`.
3. افتح تبويب «الكتب» وارفع ملفات TXT أو Markdown أو PDF أو Word حتى 100 ميجابايت.
4. شغّل المشروع:

```bash
npm install
npm run dev
```

يفتح الموقع على `http://127.0.0.1:5173`. يشغّل Vite الواجهة وAPI المحلي معًا؛ لا يحتاج التشغيل الحالي إلى Supabase أو Docker أو قاعدة بيانات خارجية. تُحفظ حسابات الفريق وجلساته محليًا في SQLite، مثل بقية مخازن التطبيق المحلية.

## دخول الفريق وحدود أمان لوحة الإدارة

توجد مصادقة محلية للفريق على `#/admin/login`. يُخفى رابط «لوحة الإدارة» عن الزائر غير المسجل، وتعرض الواجهة بعد الدخول الصفحات والأفعال التي تسمح بها صلاحيات الـprincipal فقط. إخفاء الرابط ليس ضابط الحماية: يفرض الخادم حارس صلاحيات على كل `/api/internal/**` وعلى `/api/knowledge/documents` ومساراته الفرعية الإدارية، ويرفض أي مسار أو method إداري غير معرّف افتراضيًا.

توجد الحسابات والجلسات في `data/auth.sqlite`. تُشتق الصلاحيات خادميًا من الأدوار، وتُخزن كلمات المرور كاشتقاقات `scrypt` مملّحة، ولا تحفظ قاعدة البيانات إلا SHA-256 لرمز الجلسة المعتم. تستخدم الجلسة cookie لا يقرأها JavaScript بخصائص `HttpOnly` و`SameSite=Strict`، وتضيف `Secure` واسم `__Host-` في production. يطبق الخادم انتهاءً خاملًا وآخر مطلقًا، ويدوّر الجلسة عند الدخول، ويلغيها عند الخروج أو تحديث كلمة المرور/الأدوار. تتحقق طلبات الدخول والكتابة الإدارية من الأصل الموثوق المعيّن صراحة في `AUTH_PUBLIC_ORIGIN` بدل الثقة في ترويسة `Host`.

أنشئ مستخدمًا محليًا أو حدّثه عبر `npm run auth:user` مع تمرير كلمة المرور عبر stdin، لا كوسيط أمر. مثال PowerShell:

```powershell
'كلمة-مرور-قوية' | npm run auth:user -- --email reviewer@example.org --display-name "Local Reviewer" --roles reviewer
```

يدعم الأمر الأدوار `reviewer` و`content_manager` و`operator` و`admin`، ويمكن جمعها بقائمة مفصولة بفواصل. لا يمنح دور `admin` صلاحيات المحتوى ضمنيًا. راجع [توثيق المصادقة المحلية](server/auth/README.md) للتفاصيل.

هذا تنفيذ محلي مجاني ولا يعتمد Supabase، لكنه **ليس إعلان جاهزية للنشر العام**. دورة الدعوات والاستعادة وتعطيل الحساب منفذة محليًا، وكذلك إنشاء النسخ الاحتياطية وفحصها وتنزيلها. ما زال يلزم قبل النشر العام: نقل دورة الوصول إلى تشغيل production مراقب، rate limit دائم/موزع، خادم production وHTTPS وإدارة أسرار، استعادة مختبرة في وضع صيانة وسياسات احتفاظ، حماية إساءة استخدام الواجهات العامة، واختبارات الحمل والمراجعة الأمنية. قد تبقى Telegram وPWA للمتعلم anonymous حسب قرار المنتج بعد استكمال تلك الضوابط. التفاصيل في [نطاق المنتج](docs/PRODUCT_SCOPE.md) و[خارطة الطريق](docs/ROADMAP.md).

## بوت Telegram المحلي

توجد قناة Telegram محلية اختيارية تعمل بـlong polling فقط كنسخة تجريبية مغلقة لمتعلم واحد. ولّد سر الجلسة محليًا، ثم أضف `TELEGRAM_BOT_TOKEN` فقط إلى `.env.local` وشغّل البوت:

```bash
npm run telegram:init
npm run telegram:poll
```

يتحقق التشغيل من هوية البوت ويسجل أوامره، ثم يطبع عند أول تشغيل رابط اقتران سريًا صالحًا لأول حساب Telegram يستخدمه فقط. لا تستخدم القناة webhook، ولا تحفظ chat id الخام أو نصوص المحادثة في قاعدة Telegram؛ لكن سجل الأسئلة المركزي يحفظ السؤال ونتيجة المعالجة للمراجعة. تفاصيل الإعداد والخصوصية والتعافي موثقة في [`docs/TELEGRAM_BOT.md`](docs/TELEGRAM_BOT.md).

يحفظ سجل الأمان المحلي أحداث الدخول والخروج ورفض الصلاحيات وتغييرات/نشر/استعادة إصدارات الكتب واعتماد OCR وقرارات المراجعة، ببيانات وصفية محدودة لا تحتوي الأسرار أو نصوص المحتوى. السجل append-only في الاستخدام العادي ومترابط بـHMAC لاكتشاف العبث؛ هو **tamper-evident وليس tamper-proof**. قراءة السجل وملخص integrity متاحان فقط لصلاحية `settings:manage` عبر `/api/internal/security-audit` و`/api/internal/security-audit/integrity`. تفاصيل حدود المعاملات وoutbox وتدوير المفاتيح في [توثيق سجل الأمان](server/modules/security-audit/README.md).

مفتاح التدقيق مطلوب لتشغيل الإدارة والعمليات الحساسة وتسجيل الدخول الناجح بأمان. إذا كان إعداد التدقيق غير متاح، تبقى واجهات الإجابة والإصدار العامة متاحة، بينما تفشل تلك العمليات الحساسة بحالة `503` بدل تنفيذ تغيير غير مدقّق.

## التشغيل والمراقبة والنسخ الاحتياطي

تحتوي لوحة الإدارة للحسابات التي تحمل صلاحية `settings:manage` على ثلاث صفحات تشغيلية:

- `#/admin/security-audit` لعرض أحداث الأمان المختصرة وفحص سلامة سلسلة HMAC.
- `#/admin/system-diagnostics` لفحص قواعد البيانات والتخزين وإعداد النموذج وأدوات OCR من دون شبكة أو كشف الأسرار والمسارات الخارجية.
- `#/admin/backups` لعرض النسخ المحلية وإنشائها وفحص SHA-256 وتنزيلها. تتطلب إدارة النسخ دور `admin` نفسه إضافة إلى الصلاحية الخادمية.

تُحفظ النسخ افتراضيًا في `data/backups` بصيغة `.ilabackup` ذات manifest محدد الإصدار. تشمل قواعد SQLite المدارة وملفات الكتب والفهرس، ولا تشمل `.env.local` أو المفاتيح أو مجلد النماذج القابل لإعادة التحميل. تحتوي النسخة على بيانات حساسة مثل حسابات الفريق وسجل الأسئلة والمحتوى؛ لذلك يجب حفظ الملفات المنزلة في مكان محمي.

لا تنفذ الواجهة استعادة أو حذفًا حيًا. بعد إيقاف Vite وبوت Telegram وكل كاتب محلي، تعرض أوامر الصيانة معاينة ورمز تأكيد مرتبطًا ببصمة النسخة أو قائمة النسخ الحالية، ولا تغيّر شيئًا من دون `--apply` والتأكيد المطابق:

```bash
npm run backup:restore -- --backup <uuid>
npm run backup:restore -- --backup <uuid> --apply --confirm RESTORE-<uuid>-<sha-prefix>
npm run backup:retention -- --keep 7
npm run backup:retention -- --keep 7 --apply --confirm DELETE-BACKUPS-<preview-token>
```

تشترك أوامر الصيانة والخادم والبوت وأوامر الكتابة المحلية في admission lock ذري. تفحص الاستعادة البصمات وSQLite وmigrations وسلامة سلسلة HMAC على نسخ مؤقتة، ثم تستخدم journal وrollback أثناء التبديل. إذا انقطعت العملية وتعذر إثبات اكتمال rollback، يبقى التشغيل مرفوضًا حتى يفحص المشغل journal ويكمل التعافي يدويًا. يحاول النظام مزامنة المجلدات حيث يدعم Node ونظام الملفات ذلك؛ لا يدعي ضمانًا كاملًا ضد فقدان الطاقة على Windows، ولذلك يبقى اختبار التعافي الدوري ونسخة خارج الجهاز مطلوبين.

## تدفق الإجابة

قبل البحث أو الاتصال بأي نموذج، يفحص الخادم وجود إجابة معتمدة نشطة تطابق السؤال المعياري ولغة الإجابة exact. لا تُعاد هذه الإجابة إلا بعد التأكد وقت الطلب أن جميع أدلتها ما زالت موجودة ومنشورة؛ وإلا يكمل النظام المسار العادي بأمان.

1. يختار المستخدم العربية أو الإنجليزية أو السواحيلية عند أول دخول، ويُحفظ اختياره محليًا على جهازه.
2. ترسل الواجهة السؤال ولغة الإجابة إلى `/api/answer-question` على نفس الخادم المحلي.
3. يوسّع الخادم المصطلحات غير المعروفة تلقائيًا إلى صيغ بحث عربية وإنجليزية وسواحيلية، ويحفظها محليًا لإعادة استخدامها.
4. يحوّل الخادم السؤال وصيغه والمقاطع إلى تمثيل دلالي متعدد اللغات، ثم يختار الأقرب في المعنى حتى لو اختلفت اللغة، ويضم إليه المقاطع المتتابعة من نفس الكتاب عندما تكون الإجابة ممتدة عبر صفحات.
5. إذا لم يجد دليلًا، لا يستدعي موديل الإجابة ويعيد اعتذارًا باللغة المختارة.
6. يرسل السؤال والمقاطع المختارة ولغة الإجابة إلى `deepseek-v4-flash-free` عبر OpenCode Zen.
   إذا تأخر الموديل الأساسي أو فشل مؤقتًا، تتسابق مجموعة النماذج المجانية المحددة في `OPENCODE_FALLBACK_MODELS`، ويُقبل أول رد يجتاز التحقق.
7. لا يقبل الناتج إلا إذا أشار الموديل إلى دليل صالح من المقاطع المرسلة واجتاز فحص جودة الإجراءات.
8. يفحص الخادم لغة الرد كاملة، ويرفض الإجابة المختلطة أو المخالفة للغة المختارة قبل عرضها أو حفظها، ثم يجرب نموذجًا آخر.
9. إذا تعطلت كل النماذج الخارجية، يعرض الخادم مقتطفًا محليًا فقط عندما يطابق اللغة المختارة؛ وإلا يعيد اعتذارًا آمنًا باللغة المختارة.
10. تُحفظ الإجابات الموثقة محليًا داخل `data/cache/answers.json`، فتعود الأسئلة المكررة فورًا دون استدعاء OpenCode مرة أخرى.

تحتفظ الواجهة بذاكرة قصيرة داخل جلسة المتصفح للأسئلة المتتابعة، من غير تخزين المحادثة على القرص.

## إدارة الكتب

مسار `#/admin/books` هو واجهة إدارة الكتب والإصدارات، ويحوّل المسار القديم `#knowledge` إليه للتوافق. من تفاصيل الكتاب يمكن رفع ملف مع رقم إصدار؛ يظهر progress وينتهي الإصدار عند `ready` إلى أن ينشره المشغل صراحة. تُحفظ النسخة الأصلية والنص المستخرج المرحلي والبيانات الوصفية داخل `data/documents`، ويقرأ البحث فقط الإصدارات المنشورة. يحافظ مسار مؤقت على المستندات القديمة غير المرتبطة اعتمادًا على metadata حتى ترحيلها إلى كتب وإصدارات. مجلدات المحتوى وقواعد SQLite المحلية مستبعدة من Git لحماية البيانات وتقليل حجم المستودع.

## مراجعات المعلمين

مسار `#/admin/reviews` يعرض طابور المراجعة الحقيقي مع الفلاتر والتصفح والتفاصيل والأدلة وسجل الأحداث. يمكن للمراجع المخول استلام الحالة أو إعادتها، واعتماد الإجابة كما هي، أو تحريرها واعتمادها، أو رفضها، أو طلب تعديل المحتوى. تأتي هوية المراجع من الـprincipal الذي تحققت منه الجلسة في الخادم؛ لا تُدخل يدويًا ولا تُحفظ في `localStorage`.

## التقييم ومقاييس الجودة

تظهر أسفل كل إجابة ناجحة أزرار «مفيدة/غير مفيدة». يحفظ الخادم التقييم محليًا بصورة idempotent، ويمكنه إحالته إلى طابور المعلمين حسب الخطورة أو تكرار المشكلة من دون تعديل الإجابة أو المحتوى تلقائيًا. تعرض صفحة `#/admin/quality` أرقامًا مجمعة للرضا وتغطية التقييم والامتناع والأخطاء والمراجعات واستخدام الإجابات المعتمدة، مع فلاتر الفترة واللغة والقناة ومن دون عرض نصوص الأسئلة أو الإجابات أو التعليقات.

تحمي المصادقة المحلية ومسارات الصلاحيات لوحة الإدارة، لكن المنظومة ككل ما زالت مخصصة للتشغيل المحلي والتجارب المضبوطة، ولا يجوز اعتبارها جاهزة للنشر العام قبل استكمال ضوابط التشغيل والأمان المبينة أعلاه.

ملفات PDF ذات الطبقة النصية تُقرأ مع مراعاة مواضع الأسطر والتسلسلات المرقمة حتى لا تختلط خطوات الإنفوجرافيك. أما الصفحات المصورة أو ضعيفة النص فتدخل مسار OCR محليًا باستخدام Poppler (`pdftoppm`) وTesseract، مع حفظ ترتيب الصفحات وطريقة الاستخراج ودرجة الثقة. إذا كانت الأدوات غير مثبتة لا يضيع الملف: يُحفظ الأصل ويظل الإصدار في حالة `processing` مع `ocr_required` بدل نشر محتوى فارغ. ويمكن من إدارة الكتب معاينة الأصل والنص المرحلي، وإعادة المعالجة، واعتماد النص منخفض الثقة؛ الاعتماد يجعله `ready` فقط ولا ينشره تلقائيًا.

ثبّت Poppler وTesseract وحزم اللغات المطلوبة على جهاز الخادم، ثم تأكد أن `pdftoppm` و`tesseract` متاحان في `PATH`، أو عيّن `PDFTOPPM_PATH` و`TESSERACT_PATH` في `.env.local`. اللغات الافتراضية المجانية هي `ara+eng+swa` ويمكن تغييرها عبر `OCR_LANGUAGES`. لا ينزّل المشروع محركات أو ملفات لغات تلقائيًا ولا يرسل صفحات الكتاب إلى خدمة OCR خارجية. ما زال يلزم corpus حقيقي معتمد لقياس جودة العربية والإنجليزية والسواحيلية قبل اعتبار مرحلة OCR مكتملة.

يمكن إعادة معالجة الكتب الموجودة من واجهة الإدارة، ثم تحديث الفهرس المنشور عبر `npm run prepare:semantic` عند الحاجة. ويمكن تجهيز المترجم المحلي مسبقًا عبر `npm run prepare:translation`. تُحفظ النماذج المحلية داخل `data/models`.

الكتب والبحث والـBackend محليون. يستخدم النظام OpenCode لتحسين الصياغة، وعند تعطله يترجم NLLB الدليل محليًا إلى اللغة المختارة بعد تنزيل ملفاته مرة واحدة. لا تضع معلومات شخصية أو سرية في الأسئلة المرسلة إلى OpenCode.

## تطبيق الويب القابل للتثبيت (PWA)

يوفّر المشروع PWA جزئية قابلة للتثبيت وتحتفظ فقط بواجهة التطبيق الآمنة وأصولها الثابتة. تعرض الواجهة حالة انقطاع الاتصال في تطبيق المتعلم ولوحة الإدارة، وتمنع إرسال سؤال جديد مع إبقاء مسودته، كما تطلب موافقة المستخدم قبل تطبيق تحديث جاهز. يفحص handshake محلي توافق نسخة الواجهة مع API عند الفتح وعودة الاتصال؛ يمنع عدم التوافق الإرسال حتى يوافق المستخدم على إعادة التحميل، بينما يبقى تعذر الفحص تحذيرًا غير حاجب. تم التحقق في `production preview` من manifest والأيقونات وتسجيل Service Worker وإعادة فتح غلاف التطبيق بعد إيقاف الخادم. البحث وإرسال الأسئلة وتوليد الإجابات وعمليات الإدارة تظل محتاجة لاتصال وخدمة API عاملة؛ ولا تُخزّن أسئلة المستخدم أو إجاباته أو بيانات الكتب في cache المتصفح. ما زال يلزم اختبار التثبيت الفعلي من واجهة متصفح مدعوم، ودورة تحديث حقيقية، والاتصال الضعيف والرجوع إلى online عبر HTTPS قبل اعتبار المرحلة مكتملة.
